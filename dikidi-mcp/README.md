# dikidi-mcp

MCP-сервер для DIKIDI Business, работающий **без официального API-ключа** — через
браузерную автоматизацию (Playwright) под вашей собственной учётной записью.

DIKIDI выдаёт партнёрский API-ключ только по отдельному согласованию с их
администрацией. Если вам его не выдали (или пока не выдали), этот сервер даёт
Claude доступ к тем же данным, что видите вы сами в панели DIKIDI Business —
через управляемый браузер, залогиненный вашей сессией.

## Что умеет

- `dikidi_list_services` — список услуг (название, категория, цена, длительность)
- `dikidi_list_staff` — список сотрудников/мастеров
- `dikidi_list_clients` — поиск клиентов по имени/телефону
- `dikidi_get_schedule` — записи из журнала за период, с фильтром по мастеру
- `dikidi_create_appointment` — создание новой записи клиента

**Отмена и перенос записей намеренно не реализованы.**

## ⚠️ Важно про селекторы

Этот код написан без доступа к реальному залогиненному аккаунту DIKIDI —
CSS-селекторы в `src/dikidi/selectors.ts` являются приблизительными заглушками
и почти наверняка не совпадают 1:1 с реальной вёрсткой. Прежде чем
пользоваться сервером, их нужно откалибровать по вашему аккаунту (см. ниже).

## Установка

```bash
cd dikidi-mcp
npm install
npx playwright install chromium
cp .env.example .env
```

Откройте `.env` и укажите `DIKIDI_LOGIN_URL` — точный URL страницы входа в
DIKIDI Business, которым вы пользуетесь (скопируйте из адресной строки
браузера).

## Первый вход (сохранение сессии)

Пароль в коде и в `.env` не хранится. Вместо этого один раз логинитесь вручную,
а Playwright сохраняет cookies в локальный файл:

```bash
npm run login:dev
```

Откроется окно браузера — войдите как обычно (с капчей/SMS, если есть).
После загрузки панели скрипт сам сохранит сессию в файл, указанный в
`DIKIDI_STORAGE_STATE_PATH` (по умолчанию `./.dikidi-session.json`), и
закроется.

**Файл сессии равнозначен паролю к вашему аккаунту DIKIDI.** Он уже добавлен
в `.gitignore` — никогда не коммитьте его и не пересылайте.

Если DIKIDI разлогинит сессию (истечёт срок, смена пароля и т.п.) — просто
повторите `npm run login:dev`.

## Калибровка селекторов

1. Запустите запись действий Playwright, указав ваш URL входа:

   ```bash
   npx playwright codegen --save-storage=.dikidi-session.json <ваш DIKIDI_LOGIN_URL>
   ```

2. Пройдите руками по нужным экранам: список услуг, список сотрудников,
   клиенты, журнал записей, форма создания новой записи. Playwright codegen
   покажет в соседнем окне сгенерированный код с реальными селекторами
   каждого элемента, по которому вы кликали/вводили текст.

3. Перенесите реальные селекторы в `src/dikidi/selectors.ts`, заменив
   заглушки. Структура файла один в один соответствует тому, что использует
   код в `src/dikidi/*.ts` — ничего больше менять не нужно.

4. Пересоберите и проверьте:

   ```bash
   npm run build && npm start
   ```

## Запуск

```bash
npm run build
npm start
```

или для разработки без сборки:

```bash
npm run dev
```

## Подключение к Claude Desktop / Claude Code

Добавьте в конфиг MCP-серверов (`claude_desktop_config.json` или
эквивалент в Claude Code):

```json
{
  "mcpServers": {
    "dikidi": {
      "command": "node",
      "args": ["/абсолютный/путь/до/dikidi-mcp/dist/index.js"]
    }
  }
}
```

## Ограничения этого подхода

- Это не официальный API — DIKIDI может в любой момент поменять вёрстку
  панели, и селекторы придётся обновлять.
- Не подходит для высокой частоты запросов — это реальный браузер, а не
  лёгкий REST-вызов.
- Работает только с одним аккаунтом (той сессией, что вы сохранили).
- Если DIKIDI всё же выдаст официальный партнёрский ключ — стоит
  впоследствии переписать `src/dikidi/*.ts` на прямые HTTP-запросы к API:
  это будет быстрее и надёжнее браузерной автоматизации.
