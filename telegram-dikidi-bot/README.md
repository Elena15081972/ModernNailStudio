# telegram-dikidi-bot

Telegram-бот записи клиентов в DIKIDI Business по свободному тексту.

## Как это работает

1. Клиент пишет боту: «Запиши меня на завтра на стрижку в 14:00, Елена».
2. Бот распознаёт **дату** и **услугу** из текста.
3. Бот запрашивает у DIKIDI список **свободных окошек** на этот день по этой
   услуге и показывает их **кнопками** (`InlineKeyboardMarkup`).
4. Клиент нажимает на удобное время.
5. Если это первое обращение клиента — бот просит номер телефона (кнопка
   «Отправить контакт» или текстом), чтобы найти/создать клиента в DIKIDI.
6. Бот показывает итог и кнопки «✅ Подтвердить» / «❌ Отменить».
7. **Только после нажатия «Подтвердить»** бот создаёт запись в журнале DIKIDI.

Время из текста клиента (если он его указал) сейчас не используется для
автозаписи — финальное время выбирается исключительно кнопкой, как и просили.
При желании легко добавить подсветку ближайшей к указанному времени кнопки —
см. `_offer_slots` в `bot.py`.

## Установка и запуск

```bash
cd telegram-dikidi-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` (см. разделы про ключи ниже) и запустите:

```bash
python bot.py
```

По умолчанию бот работает в режиме `DIKIDI_MODE=mock` — со встроенной
имитацией DIKIDI (случайные свободные окошки, записи сохраняются только в
памяти процесса). Это позволяет сразу проверить весь диалог с кнопками в
Telegram, не дожидаясь выдачи реального API-ключа DIKIDI. Когда получите
доступ — переключите `DIKIDI_MODE=live` и заполните `DIKIDI_COMPANY_ID` /
`DIKIDI_API_KEY`.

## Какие ключи доступа нужны

### 1. Telegram Bot Token

1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте `/newbot`, задайте имя и username бота (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAExampleTokenFromBotFather` —
   это и есть `TELEGRAM_BOT_TOKEN`.
4. Никому не пересылайте этот токен — им можно полностью управлять ботом.

### 2. DIKIDI Business API

DIKIDI **не публикует открытую REST-документацию** и не выдаёт API-ключ
самостоятельно через личный кабинет одним кликом, как Telegram. Ключ
привязывается к вашему заведению индивидуально. Порядок действий:

1. Зайдите в личный кабинет **DIKIDI Business** (business.dikidi.ru или
   dikidi.ru/ru/owner) под своим аккаунтом администратора заведения.
2. Перейдите в **Настройки → Интеграции** (в некоторых версиях интерфейса —
   «Управление пользователями» → доступ по API-ключу).
3. Нажмите **«Создать ключ»**, тип доступа — **«Администратор»**, поле
   «API-ключ» оставьте пустым — сервис сгенерирует его сам.
4. **Сразу скопируйте сгенерированный ключ** — многие интерфейсы показывают
   его только один раз.
5. Напишите в поддержку DIKIDI (или своему аккаунт-менеджеру, если он у вас
   есть) и опишите сценарий: «хочу использовать API-ключ для бота
   автозаписи клиентов через Telegram» — партнёрский доступ к API активируют
   по согласованию, это может занять некоторое время.
6. Узнайте (там же, в поддержке) **`company_id`** вашего заведения — его
   также видно в адресной строке личного кабинета, например:
   `dikidi.ru/ru/owner/journal/?company=1539128` → `company_id=1539128`.
7. Попросите у поддержки/менеджера актуальную спецификацию эндпоинтов
   (список услуг, свободное время, создание клиента, создание записи) —
   точные пути и формат ответа могут отличаться от значений по умолчанию в
   `dikidi_client.py` (переменная `ENDPOINTS` в начале файла). Поправьте их
   там при необходимости — весь остальной код (`bot.py`) обращается к DIKIDI
   только через методы `DikidiClient` и эндпоинтов не касается.

Заполните в `.env`:

```
DIKIDI_MODE=live
DIKIDI_API_BASE_URL=https://api.dikidi.ru/v1   # уточните у DIKIDI
DIKIDI_COMPANY_ID=1539128
DIKIDI_API_KEY=полученный_ключ
```

**Если официальный ключ ещё не выдали.** В этом же репозитории есть
`dikidi-mcp/` — альтернативный способ получить те же данные (список услуг,
журнал, создание записи) через управляемый браузер под вашей обычной учётной
записью DIKIDI, без API-ключа. Пока идёт согласование партнёрского доступа,
можно ориентироваться на его README, а бот тем временем тестировать в
режиме `DIKIDI_MODE=mock`.

## Автотесты (без Telegram и без DIKIDI)

Логику разбора текста (`nlp.py`) и имитацию DIKIDI (`MockDikidiClient`) можно
проверить одной командой, не поднимая самого бота и не трогая Telegram:

```bash
pip install -r requirements-dev.txt
pytest -v
```

Тесты лежат в `tests/`: `test_nlp.py` — распознавание даты/времени/имени/услуги
из фраз вроде «Запиши меня на завтра на стрижку в 14:00, Елена»;
`test_dikidi_client.py` — контракт мока (рабочие часы, шаг 30 минут,
де-дублирование клиента по телефону, исчезновение слота после записи).

## Структура проекта

- `bot.py` — обработчики Telegram (диалог, кнопки, состояния).
- `dikidi_client.py` — клиент DIKIDI API: `LiveDikidiClient` (реальные HTTP-запросы)
  и `MockDikidiClient` (имитация для разработки), общий интерфейс `DikidiClient`.
- `nlp.py` — разбор даты, времени-подсказки, имени клиента и услуги из текста.
- `models.py` — общие структуры данных (`Service`, `Staff`, `TimeSlot`, `PendingBooking`).
- `storage.py` — SQLite-кэш телефонов клиентов по их Telegram ID.
- `config.py` — чтение `.env`.

## Ограничения и что донастроить под себя

- Часовой пояс и рабочие часы задаются на стороне DIKIDI — бот их не хранит.
- Если под одну услугу и время свободны несколько мастеров, бот сейчас
  показывает одну кнопку на время (первый найденный свободный мастер). Если
  нужно, чтобы клиент явно выбирал мастера — добавьте это отдельным шагом
  перед показом слотов (аналогично шагу выбора услуги).
- Формат телефона проверяется базовым регулярным выражением — при
  необходимости замените на нормализацию через `phonenumbers`.
- Для продакшена вместо `run_polling()` можно перейти на вебхуки
  (`application.run_webhook(...)`), особенно если бот будет на сервере с
  постоянным HTTPS-адресом.
