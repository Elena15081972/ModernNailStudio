# client-support-bot

Личный Telegram-бот для владельца студии маникюра. Ты пересылаешь боту вопрос
клиента (из ВКонтакте, Авито, WhatsApp, где угодно), бот обращается к Claude
с базой знаний студии (`prompt.md`) и присылает обратно готовый текст ответа —
остаётся скопировать и отправить клиенту.

Это Этап 1 из ТЗ («ручной режим»), просто в виде бота вместо чата с Claude
напрямую — так быстрее пользоваться с телефона.

## Что делает

- Отвечает **только владельцу** — чужие сообщения бот игнорирует
  (проверка по `TELEGRAM_CHAT_ID`).
- На обычное сообщение — присылает ответ, рассчитанный на площадки, где
  ссылку DIKIDI можно давать свободно (ВК, WhatsApp, Telegram, сайт).
- На сообщение с командой `/avito <вопрос>` — учитывает, что на Авито нельзя
  сразу давать ссылки/контакты.
- Никогда не придумывает свободные окошки в расписании и не называет цену
  «от» как окончательную — эти правила зашиты в `prompt.md`.
- Если рядом настроен и собран `dikidi-mcp` (см. ниже) — на вопросы про
  свободное время реально проверяет расписание через него, а не просто
  отправляет клиента по ссылке.

## Установка

```bash
cd client-support-bot
npm install
cp .env.example .env
```

Заполни `.env`:

- `TELEGRAM_TOKEN` — токен бота, полученный у [@BotFather](https://t.me/BotFather) командой `/newbot`.
- `TELEGRAM_CHAT_ID` — твой личный Telegram Chat ID (узнать можно у [@myidbot](https://t.me/myidbot), либо открыть `https://api.telegram.org/bot<TELEGRAM_TOKEN>/getUpdates` после того, как напишешь боту).
- `ANTHROPIC_API_KEY` — ключ из [console.anthropic.com](https://console.anthropic.com/settings/keys).
- `ANTHROPIC_MODEL` — необязательно, по умолчанию `claude-sonnet-5`.
- `DIKIDI_MCP_DIR` — необязательно, см. раздел «Проверка реального расписания».

## Проверка реального расписания через dikidi-mcp

По умолчанию бот ищет соседнюю папку `../dikidi-mcp` (переопределить можно
через `DIKIDI_MCP_DIR`). Чтобы проверка расписания заработала:

1. Настрой и залогинь `dikidi-mcp` по его собственному README — включая
   калибровку CSS-селекторов под свой аккаунт DIKIDI и `npm run login`,
   иначе он не сможет прочитать реальные данные.
2. Собери его: `cd dikidi-mcp && npm run build`.
3. Просто запусти `client-support-bot` — он сам поднимет `dikidi-mcp` как
   отдельный процесс через MCP при первом вопросе про расписание.

Если `dikidi-mcp` не собран, не залогинен или падает — бот это не считает
фатальной ошибкой: он залогирует предупреждение и продолжит отвечать в
прежнем режиме (ссылка на DIKIDI вместо проверки окошек). Из инструментов
`dikidi-mcp` боту доступен только `dikidi_get_schedule` (чтение) — создание
записей (`dikidi_create_appointment`) и поиск клиентов сюда намеренно не
подключены, агент только консультирует.

## Запуск

```bash
npm run dev     # без сборки, для разработки
```

или в собранном виде:

```bash
npm run build
npm start
```

## Использование

1. Напиши боту `/start`.
2. Пришли вопрос клиента текстом — получишь готовый ответ.
3. Если вопрос пришёл с Авито — пришли его командой `/avito <вопрос>`.

## Как редактировать базу знаний

Всё содержимое ответов (адрес, график, прайс, тон, правила, примеры) лежит
в `prompt.md` — правь его напрямую, пересборка кода не нужна (файл читается
во время выполнения). Пересобери только TypeScript, если менялся код в `src/`.

## Ограничения

- Не создаёт реальную запись в DIKIDI — только помогает сформулировать ответ.
- Без настроенного `dikidi-mcp` не имеет доступа к актуальному расписанию —
  на вопросы про свободные окошки направляет по ссылке на DIKIDI, а не
  придумывает время.
- Работает только с одним владельцем (одним `TELEGRAM_CHAT_ID`).
